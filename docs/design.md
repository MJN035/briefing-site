# 장전 브리핑 사이트 — 설계 문서

- 날짜: 2026-07-30
- 소유자: 민소
- 상태: 설계 승인됨 (구현 전)

## 배경과 목적

`/뉴스` 스킬은 매일 아침 브리핑을 Artifact(HTML)로 발행한다. Artifact는 발행한 계정에만 보이고, 실행할 때마다 화면 생김새가 조금씩 달라진다. 이 프로젝트는 **고정된 UI를 가진 공개 웹사이트**를 Vercel에 배포해서, 누가 언제 열어도 같은 화면으로 그날의 브리핑을 보게 한다.

소유자의 최종 그림은 "repository를 고스란히 웹사이트화"이지만, 이번 스펙은 그 첫 서브 프로젝트인 **브리핑 사이트**만 다룬다. 문서(journey·context 등) 열람은 별도 서브 프로젝트로 미룬다.

## 확정 요구사항

1. 전체 공개 사이트. 접근 제어 없음.
2. 메인 화면 = 오늘의 브리핑 (고정 UI). 지난 날짜 이동 가능.
3. `/뉴스` 실행이 끝나면 사이트에 반영된다 — git 절차 없이, 스킬이 직접 배포 (반영 ~1분 허용).
4. 사이트에 올라가는 것은 **브리핑 데이터뿐**이다. `club/` 강의 자료, `context.md`·`journey.md`·`CLAUDE.md` 등 판단 기록, 타인 제출물은 올리지 않는다.
5. 클럽 절대 규칙 유지: 투자 조언 없음(사이트 푸터에 고지), 출처 라벨(`1차`/`2차`/`추정`) 표시, 확인 불가 수치는 `unknown` 그대로 표시.

## 선택한 접근: 정적 방식 ("repo가 곧 사이트")

`site/` 폴더의 정적 파일(HTML/CSS/JS + JSON 데이터)이 사이트의 전부다. `/뉴스`가 하루치 JSON을 저장하고 Vercel CLI(`vercel --prod`)로 배포한다. 서버·데이터베이스·비밀 토큰 없음.

기각한 대안:
- **저장소 분리(Vercel Blob + 업로드 API)**: 반영은 1초지만 업로드 토큰 관리가 필요하고, 데이터가 repo 밖에 살아 "repo = 진실의 원천"에서 멀어진다. 움직이는 부품 증가.
- **Artifact 링크 목차만 배포**: Artifact가 발행자 비공개라 "고정 UI 공개"라는 목적 자체가 달성 안 된다.

## 폴더 구조

```
site/
  index.html        # 고정 UI 골격
  style.css         # 디자인 고정판 (2026-07-30 Artifact 디자인 기반)
  app.js            # data/를 읽어 화면을 채운다
  data/
    index.json      # {"dates": ["2026-07-30", ...]} 최신이 앞
    2026-07-30.json # 하루치 브리핑 데이터
  vercel.json       # (필요시) 정적 배포 설정
```

프레임워크·빌드 없음. 이유: 고장 지점 최소화, 비개발자가 파일만 봐도 구조가 보인다.

## 데이터 스키마 (`site/data/YYYY-MM-DD.json`)

확인 불가 값은 문자열 `"unknown"`을 그대로 넣는다. 라벨 값은 `"1차" | "2차" | "추정"`.

```json
{
  "date": "2026-07-30",
  "generated_at": "2026-07-30 KST",
  "tape": [
    {"name": "코스피", "value": "5,682.74", "change": "+0.34%", "dir": "up"}
  ],
  "tape_label": "2차",
  "tape_source": "tradingeconomics · CoinDesk",
  "tape_note": "코스피 월간 -31.56% 낙폭 속 강보합",
  "tape_terms": [{"term": "", "def": "", "why": ""}],
  "items": [
    {
      "axis": "국내 거시",
      "title": "",
      "url": "",
      "why": "",
      "insight": {"read": "", "connect": "", "trap": ""},
      "waits": [""],
      "todos": [""],
      "terms": [{"term": "", "def": "", "why": ""}],
      "sources": [{"label": "1차", "name": "", "url": ""}]
    }
  ],
  "crypto": {"text": "", "url": "", "label": "2차", "terms": [{"term": "", "def": "", "why": ""}]},
  "verdict": "",
  "opened": ["1차 Fed 성명 원문", "2차 tradingeconomics"],
  "holes": ["CNBC 403 차단"]
}
```

- `dir`: `"up" | "down" | "flat"` — 색상은 국내 관례(상승=빨강, 하락=파랑).
- `items`는 정확히 3개. `axis`는 `국내 거시 | 글로벌 금융 | 테크` 중 하나(스킬 규칙과 동일).
- `waits` = "기다릴 것", `todos` = "오늘 할 것". `todos`에는 확인·기록 행동만(스킬의 조언 금지 규칙 그대로).

## UI 스펙 (고정)

2026-07-30 Artifact 디자인을 고정판으로 굳힌다:

- 구성 순서: 헤더(장전 브리핑·날짜) → 지수 테이프(가로 스크롤 칩) → 카드 3장 → 크립토 블록(별도 색) → "내 판단이 바뀌는 지점"(점선 박스) → 푸터(연 소스/구멍/조언 아님 고지).
- 카드: 축 라벨 → 제목(기사 원문 링크, `target="_blank" rel="noopener"`) → "왜 지금" 한 줄 → 접힌 인사이트 토글(`추정` 라벨, 요약줄에 "기다릴 것 N · 오늘 할 것 N") → 접힌 용어 토글 → 출처 라벨+링크.
- 사실과 해석 분리: 해석(인사이트)은 열어야 보인다. 기본값 접힘.
- 라이트/다크 모두 대응(`prefers-color-scheme` + 토큰 변수). 모바일 1열, max-width 640px.
- 헤더에 날짜 선택(이전/다음 + 목록)을 둔다. `?date=YYYY-MM-DD`로 지난 브리핑 표시. 해당 날짜 데이터가 없으면 가장 최근 날짜로 대체하고 그 사실을 화면에 한 줄로 알린다.
- `"unknown"` 값은 회색 이탤릭으로 그대로 렌더링한다.

## /뉴스 스킬 변경 (SKILL.md)

실행 순서 5번(형식) 단계를 교체한다:

- 기존: HTML을 만들어 Artifact로 발행.
- 변경: 위 스키마대로 `site/data/YYYY-MM-DD.json` 저장 → `site/data/index.json`의 `dates` 맨 앞에 날짜 추가 → `site/` 기준으로 `vercel --prod` 실행 → 사이트 URL을 참가자에게 준다.
- JSON 스키마 요약을 SKILL.md에 명시해 매일 같은 구조를 보장한다.
- `news-log.md` append(6번)와 닫는 한 줄(7번)은 그대로 유지. news-log에는 Artifact URL 대신 사이트 URL을 적는다.

## 실패 처리

- **배포 실패**: JSON은 이미 로컬에 저장돼 있으므로 유실 없음 — 다음 실행의 배포에 같이 실린다. 그날은 기존 방식(Artifact)으로 임시 발행하고, 푸터 "구멍"과 news-log에 배포 실패를 기록한다.
- **데이터 누락 날짜**: 사이트는 `index.json` 기준 가장 최근 브리핑을 보여준다.
- **JSON 형식 오류**: 스킬이 배포 전에 필수 필드(date, tape, items 3개, crypto, verdict)를 점검하고, 어긋나면 배포하지 않고 소유자에게 알린다.

## 1회 설정 (구현 시 함께)

- Vercel 프로젝트 생성·연결 (`site/` 루트, 정적 배포).
- 로컬에 Vercel CLI 인증 1회 (`vercel login` — 대화형이면 소유자가 직접 실행).
- git에는 `site/`를 커밋한다 — 사이트 코드와 데이터도 repo의 일부다(단, 배포는 git과 무관하게 CLI로).

## 성공 기준

1. `/뉴스` 한 번 실행으로 사이트에 오늘 날짜 브리핑이 뜬다 (실행 종료 후 ~1분 이내).
2. URL만 아는 제3자가 같은 화면을 본다 (로그인·설치 없음).
3. 날짜 선택으로 지난 브리핑을 열 수 있다.
4. 사이트 어디에도 매수·매도·목표가·기대수익률이 없다. 모든 수치에 출처 라벨 또는 `unknown`.

## 비범위 (이번에 안 하는 것)

- journey·context 등 문서 열람 페이지 ("repo 웹사이트화" 2단계).
- 접근 제어·로그인.
- 다른 참가자의 브리핑 수용(다중 사용자).
- RSS·알림·검색.
